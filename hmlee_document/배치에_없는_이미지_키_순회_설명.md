# 배치에 없는 이미지 키 순회란?

## 1. 간단한 답변

**배치에 없는 이미지 키 순회**는 모델이 기대하는 이미지 카메라 중 배치에 제공되지 않은 카메라를 처리하는 로직입니다.

- **목적**: 누락된 카메라 뷰를 패딩된 빈 이미지로 대체
- **이유**: 모델이 고정된 수의 카메라 입력을 기대하기 때문

---

## 2. 코드 분석

### 2.1 전체 흐름

```python
def prepare_images(self, batch):
    # 1. 배치에 있는 이미지 키 찾기
    present_img_keys = [key for key in self.config.image_features if key in batch]
    # 예: ["image_0", "image_1"] - 배치에 실제로 있는 키들
    
    # 2. 배치에 없는 이미지 키 찾기
    missing_img_keys = [key for key in self.config.image_features if key not in batch]
    # 예: ["image_2", "image_3"] - config에는 있지만 배치에는 없는 키들
    
    # 3. 있는 이미지 처리
    for key in present_img_keys:
        # 실제 이미지 전처리...
        images.append(img)
        img_masks.append(mask)
    
    # 4. 없는 이미지 처리 (핵심!)
    for num_empty_cameras in range(len(missing_img_keys)):
        if num_empty_cameras >= self.config.empty_cameras:
            break  # 허용된 개수만큼만 처리
        img = torch.ones_like(img) * -1  # 빈 이미지 생성
        mask = torch.zeros_like(mask)    # False 마스크
        images.append(img)
        img_masks.append(mask)
```

---

## 3. 왜 필요한가?

### 3.1 문제 상황

**시나리오**: 모델은 4개의 카메라를 기대하지만, 배치에는 2개만 제공됨

```python
# Config 설정
config.image_features = ["image_0", "image_1", "image_2", "image_3"]  # 4개 기대

# 실제 배치
batch = {
    "image_0": images_0,  # 있음
    "image_1": images_1,  # 있음
    # image_2, image_3 없음!
}
```

**문제**: 모델이 4개를 기대하는데 2개만 제공되면 에러 발생

### 3.2 해결 방법

누락된 카메라를 **패딩된 빈 이미지**로 대체:

```python
# image_2, image_3가 없으면
# → 빈 이미지(-1로 채움) 생성
# → 마스크는 False로 설정
# → 모델이 "이 카메라는 무시하라"고 알 수 있음
```

---

## 4. 상세 동작

### 4.1 `missing_img_keys` 생성

```python
missing_img_keys = [key for key in self.config.image_features if key not in batch]
```

**예시**:
```python
# Config
config.image_features = ["image_0", "image_1", "image_2", "image_3"]

# Batch
batch = {
    "image_0": ...,
    "image_1": ...,
}

# Result
missing_img_keys = ["image_2", "image_3"]  # 배치에 없는 키들
```

### 4.2 빈 카메라 순회

```python
for num_empty_cameras in range(len(missing_img_keys)):
    if num_empty_cameras >= self.config.empty_cameras:
        break  # 허용된 개수 초과 시 중단
    
    # 빈 이미지 생성
    img = torch.ones_like(img) * -1  # -1로 채운 이미지
    mask = torch.zeros_like(mask)    # False 마스크
    
    images.append(img)
    img_masks.append(mask)
```

**단계별 설명**:

1. **`num_empty_cameras`**: 현재까지 처리한 빈 카메라 개수 (0부터 시작)
2. **`len(missing_img_keys)`**: 누락된 카메라 총 개수
3. **`empty_cameras`**: 허용할 빈 카메라 최대 개수

### 4.3 `empty_cameras` 설정의 역할

```python
config.empty_cameras = 2  # 최대 2개까지 빈 카메라 허용
```

**동작**:
- `missing_img_keys`가 3개인데 `empty_cameras=2`이면
- 처음 2개만 빈 이미지로 생성
- 3번째는 무시 (에러 발생 가능)

## 5. 실제 예시

### 5.1 예시 1: 모든 카메라 제공

```python
# Config
config.image_features = ["image_0", "image_1", "image_2"]
config.empty_cameras = 0

# Batch
batch = {
    "image_0": torch.randn(4, 3, 224, 224),
    "image_1": torch.randn(4, 3, 224, 224),
    "image_2": torch.randn(4, 3, 224, 224),
}

# Result
present_img_keys = ["image_0", "image_1", "image_2"]  # 모두 있음
missing_img_keys = []  # 없음
# 빈 카메라 순회: 실행 안 됨 (range(0) = 빈 범위)
```

### 5.2 예시 2: 일부 카메라 누락 (허용됨)

```python
# Config
config.image_features = ["image_0", "image_1", "image_2", "image_3"]
config.empty_cameras = 2  # 2개까지 허용

# Batch
batch = {
    "image_0": torch.randn(4, 3, 224, 224),
    "image_1": torch.randn(4, 3, 224, 224),
    # image_2, image_3 없음
}

# Result
present_img_keys = ["image_0", "image_1"]
missing_img_keys = ["image_2", "image_3"]  # 2개 누락

# 빈 카메라 순회
for num_empty_cameras in range(2):  # 0, 1
    if num_empty_cameras >= 2:  # 0 >= 2? False, 1 >= 2? False
        break
    # image_2, image_3에 대해 빈 이미지 생성
    # num_empty_cameras=0: image_2 처리
    # num_empty_cameras=1: image_3 처리

# 최종 결과
images = [
    image_0,      # 실제 이미지
    image_1,      # 실제 이미지
    empty_image,  # image_2 대체 (빈 이미지)
    empty_image,  # image_3 대체 (빈 이미지)
]
img_masks = [
    [True, True, True, True],   # image_0
    [True, True, True, True],   # image_1
    [False, False, False, False], # image_2 (빈 카메라)
    [False, False, False, False], # image_3 (빈 카메라)
]
```

### 5.3 예시 3: 너무 많은 카메라 누락 (에러)

```python
# Config
config.image_features = ["image_0", "image_1", "image_2", "image_3"]
config.empty_cameras = 1  # 1개만 허용

# Batch
batch = {
    "image_0": torch.randn(4, 3, 224, 224),
    # image_1, image_2, image_3 없음 (3개 누락)
}

# Result
present_img_keys = ["image_0"]
missing_img_keys = ["image_1", "image_2", "image_3"]  # 3개 누락

# 빈 카메라 순회
for num_empty_cameras in range(3):  # 0, 1, 2
    if num_empty_cameras >= 1:  # 0 >= 1? False, 1 >= 1? True
        break  # num_empty_cameras=1에서 중단
    
    # num_empty_cameras=0: image_1만 처리
    # image_2, image_3는 처리 안 됨

# 문제: image_2, image_3가 처리되지 않아 모델 입력 형식 불일치
# → 에러 발생 가능
```

---

## 6. 빈 이미지 생성

### 6.1 빈 이미지 형식

```python
img = torch.ones_like(img) * -1
```

**특징**:
- **값**: -1로 채워짐
- **이유**: SigLIP vision encoder가 정규화된 이미지를 기대 ([-1, 1] 범위)
- **의미**: "이미지가 없음"을 나타냄

### 6.2 빈 이미지 마스크

```python
mask = torch.zeros_like(mask)  # 모두 False
```

**의미**:
- **False**: 이 이미지는 유효하지 않음
- **효과**: Attention에서 제외됨
- **결과**: 모델이 이 이미지를 무시함

## 7. `empty_cameras` 설정

### 7.1 Config 설정

```python
config = SmolVLAConfig(
    image_features=["image_0", "image_1", "image_2", "image_3"],  # 4개 기대
    empty_cameras=2,  # 최대 2개까지 빈 카메라 허용
)
```

### 7.2 사용 시나리오

**시나리오 1: Aloha 시뮬레이션**
```python
# Aloha는 3개 카메라 (top, left_wrist, right_wrist)
# 하지만 모델은 4개를 기대할 수 있음
config.empty_cameras = 1  # 1개 빈 카메라 허용
```

**시나리오 2: 단일 카메라 로봇**
```python
# 실제 로봇은 1개 카메라만 있음
# 하지만 모델은 3개를 기대
config.empty_cameras = 2  # 2개 빈 카메라 허용
```

## 8. 왜 이렇게 설계되었나?

### 8.1 유연성

- **다양한 하드웨어 지원**: 카메라 개수가 다른 로봇에서도 사용 가능
- **데이터셋 호환성**: 카메라 개수가 다른 데이터셋 처리 가능

### 8.2 모델 일관성

- **고정된 입력 형식**: 모델은 항상 동일한 수의 이미지를 받음
- **마스킹으로 처리**: 빈 이미지는 마스크로 무시됨

### 8.3 실용성

- **점진적 마이그레이션**: 카메라를 하나씩 추가/제거 가능
- **하드웨어 장애 대응**: 일부 카메라가 고장나도 작동 가능

## 9. 주의사항

### 9.1 `empty_cameras` 설정 확인

```python
# 누락된 카메라가 empty_cameras보다 많으면 에러 발생 가능
if len(missing_img_keys) > config.empty_cameras:
    # 경고 또는 에러 발생 가능
```

### 9.2 성능 영향

- **빈 이미지도 처리**: 계산 비용이 약간 발생 (마스킹으로 무시되지만)
- **메모리 사용**: 빈 이미지도 메모리 차지

### 9.3 모델 성능

- **너무 많은 빈 카메라**: 모델 성능 저하 가능
- **권장**: 최소한의 빈 카메라만 사용

## 10. 요약

### 배치에 없는 이미지 키 순회란?

**모델이 기대하는 카메라 중 배치에 제공되지 않은 카메라를 빈 이미지로 대체하는 로직**

### 핵심 포인트:

1. **`missing_img_keys`**: Config에는 있지만 배치에는 없는 이미지 키들
2. **빈 이미지 생성**: -1로 채운 패딩 이미지 생성
3. **마스크 설정**: False 마스크로 attention에서 제외
4. **`empty_cameras` 제한**: 허용할 빈 카메라 최대 개수

### 사용 목적:

- ✅ 다양한 하드웨어 지원
- ✅ 데이터셋 호환성
- ✅ 하드웨어 장애 대응

### 예시:

```python
# Config: 4개 카메라 기대
# Batch: 2개만 제공
# empty_cameras=2: 나머지 2개는 빈 이미지로 대체
```

이 메커니즘을 통해 **다양한 카메라 구성을 가진 로봇에서도 동일한 모델을 사용**할 수 있습니다!
